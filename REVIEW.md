# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72–75) | Returns `{"status": "ok"}` unconditionally without testing MongoDB connectivity. | Stopping MongoDB; `/health` still returns 200 instead of required 503. | Added `db.command("ping")` inside a `try/except` block and raise 503 on failure. |
| 2 | Startup / Indexes | No database indexes are created at startup. | Inspecting MongoDB indexes shows only default `_id`; duplicate entries allowed; query plans do `COLLSCAN`. | Created idempotent indexes in FastAPI `lifespan` handler on `employees.emp_code`, `attendance_logs.(emp_code, date)`, and query fields. |
| 3 | `compute_late_minutes` (lines 33–37) | Timezone mismatch: replaces hour/minute on UTC `punch_in` with IST `shift_start`. | Punch-in at 09:30 IST (04:00 UTC) with 09:30 shift calculates late minutes against 09:30 UTC, off by 5.5 hours. | Converted `punch_in` to IST (`UTC+05:30`) and constructed `shift_start` datetime on the IST attendance date. |
| 4 | `compute_late_minutes` (lines 36–37) | Grace period logic flaw: `int(...) > 10` drops seconds before comparing. | Punch-in at 09:40:01 IST (shift 09:30): elapsed time is 10m 1s (> 10:00 grace). Starter returns 0 instead of 10. | Evaluated total elapsed seconds strictly greater than 600 (`elapsed_seconds > 600`), then returned `int(elapsed_seconds // 60)`. |
| 5 | `compute_late_minutes` (lines 33–37) | Overnight shifts: punch-in after midnight uses the current calendar day for shift start, yielding negative or incorrect times. | Overnight shift (22:00–06:00): punch-in at 00:05 IST compared against 22:00 today instead of yesterday's 22:00. | Anchored shift start to the previous day if overnight shift punch-in is before shift end. |
| 6 | `compute_work_hours` (line 41) | Uses Python's built-in `round()`, which performs banker's rounding (round half to even). | 2.125 hours rounds down to 2.12 instead of 2.13 (R4 requires half-up rounding). | Used `decimal.Decimal` with `ROUND_HALF_UP` to round half up to 2 decimal places. |
| 7 | `compute_overtime` (lines 44–47) | Missing minimum 30-minute threshold: counts any positive overtime (`max(0, int(...))`). | Punch-out 15 minutes after shift end returns 15 instead of 0 (R3 requires $\ge 30$ min). | Added threshold condition `ot if ot >= 30 else 0`. |
| 8 | `compute_overtime` (lines 45–47) | Overnight shift end and timezone mismatch: `end` set on `date_str` and mixes aware with naive datetimes. | Overnight shift 22:00–06:00 sets shift end on shift start date; throws `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Added 1 day to `shift_end` date when `shift_end <= shift_start` and unified timezones to IST. |
| 9 | `create_employee` (lines 79–85) | Check-then-insert race condition for `emp_code`. | Concurrent requests with identical `emp_code` both pass `find_one` and create duplicates. | Created unique index on `emp_code` and caught `DuplicateKeyError` to return 409. |
| 10 | `create_employee` (lines 58–59, 82) | Missing validation for `shift_start == shift_end`; `created_at` returned as datetime instead of epoch ms. | Creating employee with identical start/end succeeds (should be 422); response schema fails because `created_at` is not epoch ms integer. | Added Pydantic validator ensuring `shift_start != shift_end`; converted `created_at` to integer epoch ms. |
| 11 | `list_employees` (line 93) | Pagination off-by-one bug: `skip = page * page_size`. | Requesting `page=1` with `page_size=20` skips the first 20 employees. | Changed offset to `skip = (page - 1) * page_size`. |
| 12 | `list_employees` (line 94) | `total` counts whole collection, ignoring active filters (`db.employees.count_documents({})`). | Filtering by department still returns total headcount across all departments. | Changed to `total = db.employees.count_documents(q)`. |
| 13 | `list_employees` (line 95) | Missing sorting: results returned in natural MongoDB insertion order. | Response order is non-deterministic. | Added `.sort("emp_code", ASCENDING)` per contract. |
| 14 | `punch_in` (lines 101–102) | Missing check for non-existent employee; raises 500 `TypeError` on `emp["shift_start"]`. | Punch-in with unknown `emp_code` crashes with 500 instead of 404. | Added explicit check `if not emp: raise HTTPException(404)`. |
| 15 | `punch_in` (lines 102–103) | Instants not truncated to whole seconds (R1); naive local date calculation. | Punch-in with fractional milliseconds stores sub-seconds; overnight punch-ins attributed to wrong calendar date. | Truncated instants to whole seconds; calculated IST attendance date with overnight shift logic. |
| 16 | `punch_in` (lines 104–105) | Check-then-insert race condition on `(emp_code, date)`. | Concurrent punch-ins for the same employee and day both get 201. | Created compound unique index on `(emp_code, date)` and caught `DuplicateKeyError` to return 409. |
| 17 | `punch_in` (lines 119–120) | Injects `"id": str(res.inserted_id)` into response document. | OpenAPI schema validation fails because `AttendanceRecord` has no `id` field. | Omitted `_id` and removed `id` assignment. |
| 18 | `list_attendance` (lines 144–147) | Loads entire collection into memory (`list(db.attendance_logs.find(q))`) and sorts in Python. | High memory consumption and latency on 100,000 documents. | Applied database-level `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`. |
| 19 | `list_attendance` (lines 127–128) | Missing validation for `date_from > date_to`. | Querying `date_from=2026-07-10&date_to=2026-07-01` returns 200 with empty list instead of 422. | Added validation raising 422 if `date_from > date_to`. |
| 20 | Boundary conversions | BSON datetimes returned as raw objects/strings instead of epoch milliseconds. | Client receives ISO strings or BSON dicts for `punch_in`, `punch_out`, and `history.at`. | Added boundary formatters (`to_epoch_ms`) converting all instants to integer milliseconds. |

---

### Non-Defects Examined
1. **Storing dates and times as strings (`YYYY-MM-DD`, `HH:MM`)**: Examined whether these fields should be stored as BSON datetimes. Confirmed per `DATA_MODEL.md` Section 1 that storing calendar dates and times of day as strings is intentional to prevent unwanted timezone shifts.
2. **PyMongo timezone awareness**: Checked whether to rely on PyMongo's default `tz_aware=False`. Setting `tz_aware=True` on `MongoClient` ensures that datetimes returned from MongoDB are explicitly UTC-aware, preventing subtle timezone bugs when converting to IST.
